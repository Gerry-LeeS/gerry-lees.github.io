Metasploit & EternalBlue —
Gaining Access to a Windows Machine

CVE-2017-0144 — EternalBlue — CVSS 8.1 / 10 — High

Learning Metasploit fundamentals and applying them to exploit a real vulnerability — from initial scan to admin access, credential dumping, and flag recovery.

What is Metasploit

Metasploit is an exploitation framework — a tool that organises and automates the process of finding and using exploits against target systems. Rather than building exploits from scratch, you search for a known vulnerability, configure it with target details, and run it. It's widely used in penetration testing and security research, and understanding how it works is useful from both an offensive and defensive perspective.

The Blue room on TryHackMe puts this into practice with minimal guidance — given only a target IP, the goal was to identify what the machine was vulnerable to and exploit it.

What is EternalBlue

EternalBlue (CVE-2017-0144) is an exploit targeting a vulnerability in the Windows SMB protocol. SMB runs on port 445 and is used for sharing files and resources across a network. EternalBlue allows an attacker to gain unauthorised remote access to a vulnerable machine without needing credentials. Port 445 has historically been heavily targeted, and a large number of unpatched machines remained vulnerable to EternalBlue long after the patch was available — which is part of why it became so widely known and used.

EternalBlue was famously used in the WannaCry ransomware attack, which caused widespread damage across organisations globally. It was originally developed by the NSA before being leaked publicly.

Why this matters for defenders

EternalBlue is old. The patch has been available since 2017. The fact that it still appears in CTF rooms and real-world breaches years later is a direct consequence of poor patch management. An unpatched machine running SMB on port 445 is a known, documented, easily exploitable target.

Step 1 — Reconnaissance

The first step with no hints given was a general Nmap scan to find open ports.

# Initial scan — find open ports $ nmap <target-ip>

This showed all open ports but not enough detail to answer what the machine might be vulnerable to. A version and script scan was needed next.

# Version and default script scan $ nmap -sV -sC <target-ip>

This returned version information for each service. Port 445 stood out — it was running an older version of the SMB service. Given that port 445 has historically been heavily targeted, it was the obvious place to look for vulnerabilities.

# Scan port 445 specifically for SMB vulnerabilities $ nmap --script smb-vuln* -p 445 <target-ip>

This confirmed the machine was vulnerable to EternalBlue.

Step 2 — Exploitation with Metasploit

With the vulnerability identified, the next step was finding and configuring the right exploit in Metasploit.

# Launch Metasploit $ msfconsole # Search for the EternalBlue exploit msf6 > search eternalblue # Select the exploit, set target IP, choose payload, run msf6 > use <exploit module> msf6 > set RHOSTS <target-ip> msf6 > set payload <payload> msf6 > run

Step 3 — Shell to Meterpreter

The exploit landed an initial shell — a basic command prompt on the target. This was then backgrounded and upgraded to a Meterpreter shell, which provides more built-in functionality and is more stable to work with.

# Background the current session meterpreter > background # Upgrade shell to Meterpreter using post exploit module msf6 > use post/multi/manage/shell_to_meterpreter msf6 > set SESSION <session id> msf6 > run

Step 4 — Process Migration

After getting a Meterpreter session, the next step was process migration. The process Metasploit initially lands in can be unstable and get terminated. Migrating into a more stable process keeps the session alive and can give access to higher privileges depending on what process you migrate into.

# List running processes meterpreter > ps # Migrate into a stable process meterpreter > migrate <PID>

Step 5 — Credential Dumping and Hash Cracking

With admin access established, the next step was dumping the password hashes from the machine using Meterpreter's built-in hashdump command.

meterpreter > hashdump # Returns usernames and their hashed passwords

The hashes were Windows NTLM hashes — a well known format that has been cracked extensively. Because of this, an online hash cracker was able to look the hash up in a precomputed table and return the plain text password immediately. If the hash had been a stronger or less common algorithm, John the Ripper or Hashcat with a wordlist would have been the approach instead.

Step 6 — Flag Recovery

The final stage was navigating the filesystem to find three flags stored in key locations — including Program Files, the SAM directory, and admin files. Having admin access meant no restrictions on where the filesystem could be explored.

Key Takeaways

  • A version scan with -sV -sC reveals service versions — the starting point for identifying what a machine might be vulnerable to
  • Nmap's --script smb-vuln* flag can confirm specific SMB vulnerabilities before attempting exploitation
  • Metasploit organises exploits into searchable modules — finding and configuring the right one is straightforward once the vulnerability is identified
  • Meterpreter is more capable and stable than a basic shell — upgrading early makes post-exploitation easier
  • Process migration keeps a session alive and stable after initial access
  • Windows NTLM hashes are widely cracked — strong, unique passwords matter even when hashed
  • EternalBlue is from 2017 and still appears in real environments — patch management remains one of the most important defensive practices
