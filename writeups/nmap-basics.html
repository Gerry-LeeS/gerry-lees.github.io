Nmap — Scanning, Open Ports,
and What They Reveal

My first real network reconnaissance — finding open ports, identifying a hidden service, and understanding why this matters from a defender's perspective.

What is Nmap

Nmap (Network Mapper) is one of the most fundamental tools in both offensive and defensive security. At its core it does one thing — scans a network or host to discover what ports are open and what services are running on them. For a SOC analyst, understanding Nmap matters in two directions: using it to map your own environment, and recognising when an attacker is using it against you.

The Objective

The goal of this exercise was to identify the name and version of a web server running on a target machine. No other information was given. This mirrors a real-world scenario where you need to understand what's actually running on a system — not just what should be running on it.

Step 1 — General Scan

The first step was a general TCP connect scan to find all open ports on the target. A -sT scan completes the full TCP three-way handshake — more detectable than a SYN scan, but reliable and usable without elevated privileges.

$ nmap -sT <target-ip> # Key result: PORT STATE SERVICE 8008/tcp open http

Port 8008 came back open and running HTTP. This is immediately interesting — port 80 is the standard port for HTTP. Something running HTTP on port 8008 is either a secondary service, a development server, or potentially something that someone doesn't want easily found.

SOC note — non-standard ports

A service running on a non-standard port is worth investigating. It could mean a legitimate secondary service — or it could indicate a threat actor running something through a compromised machine and deliberately avoiding port 80 to stay under the radar. Port obfuscation is a real technique. A SOC analyst seeing unexpected HTTP traffic on an unusual port should treat it as suspicious until proven otherwise.

Step 2 — Version Detection on Port 8008

A general scan tells you a port is open. It doesn't tell you what's actually running on it. For that, the -sV flag instructs Nmap to probe the service and return its name and version. The -Pn flag was also needed here — the target was configured to appear offline to ping requests, so without -Pn Nmap would have skipped it entirely.

$ nmap <target-ip> -Pn -sV -p 8008 # Result: PORT STATE SERVICE VERSION 8008/tcp open http lighttpd 1.4.74

That's the answer — lighttpd 1.4.74. A lightweight open source web server. Version detection matters because specific versions carry specific known vulnerabilities. If you know a target is running lighttpd 1.4.74, you can check immediately whether that version has any published CVEs.

Scan Types — and Why It Matters

Flag Scan type What to know
-sT TCP Connect scan Full three-way handshake. Reliable, but leaves logs — more detectable
-sS SYN scan (stealth) Sends SYN, doesn't complete handshake. Faster and quieter — requires root privileges
-sV Version detection Probes open ports to identify service name and version — critical for vulnerability assessment
-Pn Skip host discovery Treats host as online even if it doesn't respond to ping — needed when ICMP is blocked
-p Specify port(s) Targets a specific port rather than scanning all — useful when you already know what to look at
SOC note — scan type as an indicator

The difference between -sT and -sS matters from a defensive perspective too. A SYN scan is specifically designed to avoid detection — if you're monitoring network traffic and see incomplete TCP handshakes across multiple ports in quick succession, that's a strong indicator of reconnaissance activity. Knowing how attackers scan helps you recognise when you're being scanned.

Dangerous Open Ports — A Defender's Perspective

Not all open ports are equal. Some represent services that should simply never be running on a modern system. The clearest example is Telnet on port 23 — a protocol that sends everything including usernames and passwords in plain text with zero encryption. SSH replaced Telnet specifically because of this. Finding port 23 open on a system during a scan is an immediate red flag.

This is why port awareness is foundational for SOC work. A list of open ports on a machine tells you its attack surface. Ports that shouldn't be open, services running on non-standard ports, and old unpatched versions are all things that show up in Nmap output — and all things an attacker looks for first.

Key Takeaways

  • Nmap is foundational — understanding it from both offensive and defensive angles is essential for SOC work
  • A general scan finds open ports — version detection tells you what's actually running and whether it's vulnerable
  • -Pn is necessary when a host is configured to appear offline — don't assume no response means no host
  • Non-standard ports are worth investigating — legitimate services and threat actors both use them, for different reasons
  • Scan type reveals intent — incomplete TCP handshakes across multiple ports is a classic reconnaissance signature
  • Telnet on port 23 should never be open — plain text credentials are an immediate critical risk
