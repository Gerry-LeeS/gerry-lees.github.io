Phishing Analysis —
Headers, Attachments, and Malicious Files

Analysing phishing emails through header inspection, typosquatting detection, file hashing, VirusTotal, and REMnux — including a two-stage payload disguised as a PDF.

Why Phishing Analysis Matters

Phishing is one of the most common initial access vectors in real breaches. A SOC analyst needs to be able to triage a reported phishing email quickly — determine whether it's malicious, what it's trying to do, and whether anyone clicked anything. This section of SOC Level 1 covers the practical skills for doing exactly that.

Email Headers — Finding the Real Source

The displayed sender name and address in an email can say anything — they're trivially easy to fake. The real source of an email is in the headers, which contain the actual sending server's IP address and routing information.

Viewing the page source or raw headers of a suspicious email exposes the originating IP. When that IP doesn't match the domain the sender is claiming to be from, that mismatch is a red flag — the email wasn't sent from the legitimate server it claims to represent. The sending server belongs to the attacker, not the organisation being impersonated.

# Key headers to check in a suspicious email Received: — shows the actual sending server and IP From: — the displayed sender — easily faked Reply-To: — where replies go — often different from From in phishing Return-Path: — where bounces go — another indicator of real origin

Typosquatting

Typosquatting is the technique of registering a domain name that closely resembles a legitimate one — close enough that a quick glance won't catch it. A classic example would be using goog1e.com instead of google.com, substituting a number for a letter.

In phishing emails this is used to make the sender address look legitimate at a glance. Someone checking quickly whether an email came from a real company domain might not notice a single character substitution or an added letter. Slow down and check carefully — the domain needs to match exactly.

Common typosquatting patterns

Character substitution (o → 0, l → 1), added characters (paypa1.com → paypa1l.com), swapped characters (amazon → amzaon), different TLD (company.com → company.net). Any of these on a sending domain warrants immediate suspicion.

File Analysis — Hashing and VirusTotal

When a suspicious attachment needs to be analysed, the rule is simple — never run it. Instead, hash it and check the hash, or upload it to a sandbox.

Hashing the file preserves its integrity and gives you a fingerprint to check against threat intelligence databases. Some malware is capable of modifying itself to avoid detection, but at a specific point in time a hash is an exact identifier of that specific file.

VirusTotal takes that hash and checks it against a database of known malicious files — but it also does more than that. It runs the file through dozens of antivirus engines simultaneously and returns what each one detected. Even if the specific hash isn't in the database yet, the engines may still flag the behaviour or characteristics of the file.

# Hash a file without running it sha256sum suspicious_file.pdf # Submit the hash to VirusTotal rather than the file itself # if the file contains sensitive data you don't want uploaded

REMnux — Analysing a Disguised Executable

One exercise involved analysing a file named invoice.pdf that was flagged as suspicious. On Windows, the file showed as a shortcut rather than a PDF — an immediate indicator that something was wrong. A legitimate PDF has no reason to be a Windows shortcut file.

The file was transferred to a REMnux Linux environment for safe analysis without risk of execution. REMnux is a Linux distribution specifically built for malware analysis — it provides tools to examine files without running them.

Analysis revealed that the shortcut was configured to execute a PowerShell command on click. That command would disable a security alert and then reach out to an external location to download a second stage payload — the actual malware. The initial file itself was essentially just a delivery mechanism, clean enough to avoid basic detection, with the real malicious code pulled down after execution.

Two-stage payloads

Delivering malware in two stages is a common evasion technique. The first file — in this case a disguised shortcut — may pass basic checks because it doesn't contain the malicious code directly. The real payload only arrives after the victim has already executed the first file. This is why file type verification and sandboxed analysis matter even for files that initially appear clean.

Phishing Indicators — What to Look For

Urgency Subject lines or body text designed to create panic or pressure — "Your account will be closed", "Immediate action required". The goal is to make the target act before thinking.
Grammar Poor spelling and grammar. Legitimate companies typically have someone review outbound communications. Errors are a common sign of a non-native speaker or automated generation.
Domain Sender domain doesn't exactly match the organisation being impersonated. Check for typosquatting — character substitutions, added letters, different TLDs.
Headers Source IP in the email headers doesn't match the claimed sender domain. The Reply-To address differs from the From address.
Attachments Any attachment should be treated with suspicion. An executable masquerading as a document, a shortcut file named as a PDF, or any file prompting you to enable macros are all red flags.
Spear Spear phishing is targeted — the attacker knows the victim's name, role, and what they might be expecting. "Hi John, here's the Q1 report you requested" is far harder to detect than a generic phishing attempt because everything matches what the target expects to receive.

Key Takeaways

  • Email headers reveal the real source IP — a mismatch with the claimed sender domain is an immediate red flag
  • Typosquatting relies on a quick glance — slow down and verify the domain character by character
  • Never run a suspicious file — hash it and check against VirusTotal, or analyse it in a safe environment like REMnux
  • VirusTotal runs files through dozens of antivirus engines simultaneously — more thorough than a single hash lookup
  • A file showing as a Windows shortcut when named as a PDF is an immediate indicator of disguise
  • Two-stage payloads keep the initial file clean — the real malware arrives only after execution
  • Spear phishing is the hardest to detect — targeted, personalised, and designed to match exactly what the victim expects
